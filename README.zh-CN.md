# 自然写作工作流

这是一个可移植的写作编辑 Skill。它把自然表达、作者声线与信息保真放在同一条流程里，并提供按需发现和评估新方法的入口。

[English](README.md)

## 解决什么问题

用一套主编辑策略改善套话、重复铺垫和机械句式，再对照原文检查事实、引用、限定条件和作者观点。候选工具可以更换，但不能因为版本更新、热度更高或自报检测成绩，就自动替换当前策略。

普通润色可离线完成。你提出“更新候选”“比较最新方案”时，才进入有边界的在线核验；本包不会在后台自行运行。

## 如何使用

让支持 `SKILL.md` 的 Agent 读取 [Skill 入口](human-writing-workflow/SKILL.md)，或在审阅后将整个 `human-writing-workflow` 文件夹放入该 Agent 支持的技能目录。需要同时保留 `references/`，不需要安装脚本、模型或付费 API。

示例：

> 用 $human-writing-workflow 润色这份英文报告。保持自然、适度正式的课程报告语气，保留全部数字、引用、研究限制和我的立场。只返回正文。

> 用 $human-writing-workflow 改这段中文。不要编造经历或情绪，不要为了像人写而故意加错字。

> 用 $human-writing-workflow 更新学术英文候选，最多查三个新方法，先给比较和变更提案，不要安装或替换现有规则。

> 用 $human-writing-workflow 只审阅这次改写有没有改变原意，不要替我重写。

## 三个模式

| 模式 | 交付 | 边界 |
| --- | --- | --- |
| revise | 润色后的文本 | 一次主编辑加一次定向修正，不反复套多套提示词 |
| assess | 对改写或候选的评估 | 评估不默认授权编辑、安装或外传 |
| refresh | 带日期的候选比较与变更提案 | 按需查询公开来源，不自动晋升、不建立定时任务 |

## 怎样选择更好的方法

先检查保真与权限边界，再比较目标文体里的清晰度、连贯性和作者声线。新候选先做同题试用，通过相同的合成用例后，才建议成为某一文体的默认策略。一次满意的改写不足以证明它全面最优。

Stars 代表累计关注；安装遥测不等于活跃使用；版本号不代表已核验 Git tag；仓库最近 push 也不一定是写作规则更新。候选登记分别记录来源审阅和行为评估，不能互相冒充。

学术写作保留必要的被动语态、术语和谨慎表达，不能把“可能”改成“确定”、相关改成因果、计划改成完成。个人声线优先依据作者提供的样本，不能虚构感受或经历。英文编辑习惯也不能机械套用到中文。

## 持续更新的含义

本包提供可重复的刷新与评估协议，不承诺自行持续在线。需要最新信息时，由当前 Agent 在已有权限内做有限的公开资料检查；遇到登录、付费或来源无法核实时，报告缺口并继续使用合适的已接受基线。

普通文本编辑不会偷偷更新候选 JSON 或已安装 Skill。刷新先形成可审阅提案；只有用户要求把指定结果写入某个位置，才保存相应更新。定时运行、GitHub 发布、外部上传和安装都需要独立授权。

## 隐私与交付

本包只有 Markdown、YAML 和 JSON，没有可执行脚本、网络客户端或后台调度。当前文稿、作者样本和私密资料不会默认发送给候选工具网站或评分服务。

它改善表达与信息保真，不保证 AI 检测分数，也不把风格当作作者身份鉴定。遵守适用的声明要求；正文不自动附加编辑日志或说明。

行为检查材料见 [evaluations/README.md](evaluations/README.md)。它们是新写的合成材料，没有包含真实作业、身份或提交数据。
